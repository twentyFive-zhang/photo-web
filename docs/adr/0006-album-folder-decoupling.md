# 专辑与网盘目录彻底解耦：显式成员关系取代目录派生（修订 ADR 0002、0005 注记）

取代 ADR 0002 中「下行：新文件夹自动创建同名专辑并导入其中照片」「专辑重命名跟随网盘 rename」的结论（上行推送机制、删除不自动传播、网盘不做运行时图床继续有效）；修订 ADR 0005 注记（JIANGLIUER-102）中「解除托管 → 按目录重新导入 → 专辑按目录名重建」的恢复语义。ADR 0004 的托管文件与直接管理通道不受影响。

## 决策

- **专辑与网盘目录之间不存在任何对应，包括派生**：目录名不再由专辑标题派生（`sanitizeNetdiskName` 退役），专辑改名是纯站内操作，不再触发网盘 rename 与照片 path 前缀修正。
- **照片独立于专辑**：照片与专辑经成员关系多对多关联（关联表持有专辑内顺序），`Photo.albumId` 废弃；照片可以不属于任何专辑。
- **母版落点统一**：推送的母版统一放 `/apps/{应用名}/library/`（publicId 命名）。系统按 fsId 索引照片与网盘文件，`netdiskPath` 降级为可修正缓存——管理员在网盘 App 内自由移动、改名、建目录，扫描刷新缓存，目录结构不再有任何系统语义。
- **收编两段式**：导入弹窗只负责把网盘文件登记为照片（fsid 索引 + 拉取生成变体）；专辑编辑页从照片中挑图组成专辑。不持久化专辑与来源文件夹的关联。
- **下行扫描降级**：只做三件事——发现待导入文件、刷新已索引文件的路径缓存、报告母版丢失；不再自动建专辑、不再自动导入。
- **删除不变量：系统永不删除网盘文件**。站内删除照片 = 移除索引，网盘文件原地回到待导入状态。「托管归档」状态与复活防护退役：下行扫描不自动导入后，复活在结构上不可能，重新导入即撤销删除。
- **存量不迁移**：本地库清空从零开始（Admin 与百度凭据保留），网盘既有文件原地保留，作为待导入原料重新收编。

## 理由

- 标题→目录名派生链同时驱动推送落点、改名传播、扫描建专辑三处行为，是「专辑跟文件夹走」的全部根源；拆掉派生，三处一并简化，专辑命名从此只受产品语义约束（sanitize 冲突、改名联动一并消失）。
- 网盘是档案库不是组织工具：fsid 跨移动/改名稳定，系统本就不该关心目录形状；管理员的网盘整理自由与站内策展彻底正交。
- 多归属让「年度精选与主题专辑共用照片」成为一等公民；从零建库使其迁移成本为零，是选它的最低成本时刻。
- 「数据库只是网盘的索引」+「系统永不删网盘文件」组合出安全不变量：清库、误删、bug 都炸不到母版，母版唯一删除路径是管理员的手。

## 代价

- 专辑成员不再由目录结构隐含：新照片入库需要「导入 + 挑图」两步，比「丢进同名文件夹」多一次操作。
- JIANGLIUER-102 的「网盘归档（托管）」设置卡片语义被待导入清单取代，按目录重建专辑的恢复路径退役。
- 存量专辑与变体废弃，变体需在重新导入时再生。

2026-11-22 经 grilling 决策会确定全部分支（12 项拍板）；实现随本 ADR 同步落地，本地库清空重建。
