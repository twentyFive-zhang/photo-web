# 百度网盘与发布库双向同步（修订 ADR 0001）

取代 0001 中「网盘只做导入源（单向）、反向备份暂不做」的结论；其「网盘不做运行时图床」部分继续有效。

## 决策

发布库（本地存储，M6 后为 COS）是照片**原件的唯一权威存储**；百度网盘 `/apps/{应用名}/` 目录作为发布内容的**热备份镜像**，与站内双向同步：

- **上行**：站内新增/存量照片原件自动异步推送到网盘（BullMQ 队列，三阶段上传）；专辑重命名/照片换专辑时跟随 rename/move。
- **下行**：定时增量扫描（每日，可关）+ 手动触发。新文件夹自动创建同名专辑（默认仅链接可见）并导入其中照片；已有映射文件夹中的新照片自动导入。
- **删除**：任何方向的删除都不自动传播。站内删除 → 标记「待确认删除」，人工确认后才删网盘（API 删除是否进回收站无文档承诺，按不可恢复对待）；网盘侧删除 → 仅报告缺失，站内照片永不动。
- **冲突**：同名不同内容按新照片处理，站内照片永不被网盘覆盖。

## 理由

- 网盘不当运行时存储的原始动机（合规、临时签名链接、访客体验绑在网盘限速上）全部成立，因此权威存储与图床仍在 COS/CDN；同步只提供「网盘有一份」的备份价值。
- 网盘 API 仅能访问 `/apps/{应用名}/`，且普通用户分片固定 4MB、有限流与配额错误——这些约束天然适合异步备份路径，不适合关键路径。
- 删除采用最保守语义：双向自动删除是同步类系统最大的误删来源，个人站点多一步人工确认的成本远低于数据丢失。

## 代价

- 需要维护站内照片 ↔ 网盘 fs_id 的映射（`Photo.netdiskFsId`）与待确认删除列表。
- 上行引入额外队列负载；存量照片需一次性全量回填。
- 「秒传」加速无文档承诺，只能传 MD5 参数碰运气，不能依赖。

2026-10-28 经 grilling 决策会确定全部分支；实现记为里程碑 M5.5。
