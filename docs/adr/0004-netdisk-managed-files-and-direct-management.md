# 网盘托管文件与直接管理通道（修订 ADR 0002）

取代 0002 中「网盘 = 发布内容的纯镜像」的定位，其余结论（双向同步、删除不自动传播、权威存储仍在发布库）继续有效。

## 决策

网盘应用目录（`/apps/{应用名}/`）里存在**两类内容**：

- **镜像文件**：站内照片的上行备份，与 `Photo` 表通过 `netdiskFsId`/`netdiskPath` 建立映射，受每日扫描、补推、pending-delete 流程管理。
- **托管文件**：管理员从 `/admin/netdisk` 直接上传的任意格式文件（归档、视频、源文件等）。不进 `Photo` 表、不进相册、前台不可见；仅在 `SiteSetting.netdiskManagedFiles` 登记 fsId/path，供下行扫描**跳过**（托管文件不进任何照片流程），登记随扫描自愈修剪。

后台新增**直接管理通道**（与镜像同步流程并存、互不干扰）：

- **新建文件夹**：落点为当前浏览目录，路径边界强制在 `/apps/{应用名}/` 内；同名冲突（百度 create rtype=2）返回 409 提示。
- **删除（单删/批删/文件夹级联共用一个路径数组端点）**：走百度 filemanager delete，进网盘回收站；页面不提供回收站管理。删除命中镜像文件时（按 `Photo.netdiskPath` 精确/前缀匹配）**即时清除**对应照片的 `netdiskFsId`/`netdiskPath`，照片变回「未推送」，由既有全量推送/按专辑补推恢复镜像；不触碰 `NetdiskPendingDelete` 表。删除操作一律经确认弹窗二次确认。
- **直接上传**：单文件 ≤2GB（超限 413）、格式完全不限制；服务端临时落盘（os.tmpdir）→ BullMQ 队列分片推百度（4MB 对齐，复用照片推送的三阶段管线）→ 页面轮询显示「后台上传中」与最近任务状态（任务即 BullMQ job，不入库，保留 7 天）；刷新/关页不中断队列任务。

## 理由

- 托管文件若不与照片流程隔离，每日扫描会把上传的图片文件自动导入成照片，破坏「托管 ≠ 照片」的边界；登记 fsId 是最小成本的隔离手段（无新表、随扫描自愈）。
- 删除仍走最保守语义：不自动传播到站内照片本体（镜像映射清除 ≠ 删照片），且进回收站留后悔药；页内删除是管理员显式动作，无需再叠一层「待确认删除」记录。
- 上传复用既有分片管线（precreate → superfile2 → create），限流、token 刷新、秒传探测的行为与照片推送完全一致，不引入第二套上传实现。

## 代价

- 托管文件无站内清单页：文件列表即网盘树本身，登记仅用于扫描隔离；在网盘客户端手动删除托管文件后登记由扫描自愈清除。
- 删除镜像后照片回到「未推送」，不会出现在扫描报告的「缺失」列表里（缺失语义 = 网盘侧删除且映射未清，用于发现**绕过本页**的删除）；恢复走全量推送/按专辑补推。
- 上传临时文件占用 /tmp 磁盘（单文件最大 2GB，上传完成即删）；系统清理 /tmp 会让残留任务以「临时文件已不存在」失败，重新上传即可。
